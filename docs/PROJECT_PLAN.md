## 1. 研究问题与动机

**问题。** 部署在边缘设备上的人脸识别模型需要压缩，而真实场景里人脸经常被口罩、墨镜、手、头发等遮挡。剪枝通常根据"参数有多重要"决定删掉哪些权重，但重要性几乎总是在**干净数据**上估计的（或者干脆只看权重大小）。

**为什么这是个问题。** 已有研究发现，剪枝对整体准确率影响很小时，对少数、困难或分布外的样本的伤害却不成比例（Hooker et al., 2019；Liebenwein et al., 2021）。遮挡人脸正是这类困难输入：模型在遮挡下依赖的可能是另一批权重，例如利用未被遮挡区域的特征、或在缺失信息时做补偿的通道。如果只用干净数据判断重要性，这些权重可能因为在干净图上"不重要"而被剪掉。

**想法。** 让重要性估计"看见"我们关心的条件：分别在干净和合成遮挡的输入上计算一阶 Taylor 重要性，逐层归一化后加权合并，再按合并分数剪枝。方法本身不需要额外的优化过程，只改变**用什么数据来估计重要性**。

**假设。** 在相同稀疏度和相同打分预算下，融合干净与遮挡重要性，比只用其中一种或只看权重大小，能在遮挡输入上保留更高的准确率，同时不明显损害干净准确率。

**我们不预设结论。** baseline 阶段的诊断（第 7 节）已经给出一个可能对 OAGP 不利的现象：干净数据上的梯度信号非常弱。项目的价值在于把"OAGP 有效 / 无效 / 为什么"讲清楚。

**定位（展示时的说法）：** 现有剪枝准则要么只依赖权重本身，要么在干净数据上估计重要性；鲁棒性感知的方法则针对对抗扰动且需要额外优化。我们研究一个更轻量的问题：只改变**估计重要性所用的数据分布**，在固定打分预算下能否保住遮挡鲁棒性，并分析它在什么条件下有效、什么条件下无效。

## 3. 方法

### 3.1 问题定义

ResNet-18 分类器 $f_w$，参数中可剪枝的部分记为 $\mathcal{P}$（见 3.5）。对每个可剪枝层 $l$，给定目标稀疏度 $p$，选择二值掩码 $m_l \in \{0,1\}^{|w_l|}$，满足 $\|m_l\|_0 = \lfloor (1-p)\,|w_l| \rfloor$，剪枝后模型为 $f_{w \odot m}$。我们希望 $f_{w\odot m}$ 在干净输入和遮挡输入上都保持高准确率。

### 3.2 合成遮挡算子

$x^{occ} = T_M(x)$：在 $[0,1]$ 像素空间、ImageNet 归一化之前，把一个正方形区域置为黑色（0）。面积比例 $r$ 指占**整张图**的比例，不是可见人脸面积；正方形边长 $s=\mathrm{round}(\sqrt{r\,HW})$，位置在图内均匀随机。

### 3.3 重要性准则

所有梯度类准则都在**同一个 Dense-Aug checkpoint** 上计算，BN 处于 eval 模式（与推理一致，也避免小 batch 下 BN 统计失效）。

- **Random**：随机分数（下界）。
- **Magnitude**：$I_j = |w_j|$。
- **一阶 Taylor（逐样本估计）**：对打分集合 $\mathcal{S}$ 中每个样本单独反传，
  $$I_j(\mathcal{S}) = \frac{1}{|\mathcal{S}|}\sum_{n\in\mathcal{S}} \left| w_j \,\frac{\partial \ell(x_n, y_n)}{\partial w_j} \right|$$
  这正是"逐样本绝对贡献的期望"的无偏估计。我们**不用** mini-batch 版本 $|w_j\,\partial L_b/\partial w_j|$ 作为主方法：后者先对 batch 求平均梯度再取绝对值，同一 batch 内的正负贡献会相互抵消，与上式不等价。由于预算只有 128 个样本，逐样本反传在 GPU 上只需数秒；mini-batch 版本作为消融。
  - **Clean-Taylor**：$\mathcal{S}$ = 128 张干净训练图。
  - **Occ-Taylor**：$\mathcal{S}$ = 128 张遮挡训练图（遮挡比例 ~U(10%, 30%)）。
  - **Mixed-Taylor**：$\mathcal{S}$ = 64 干净 + 64 遮挡，直接合并计算，不做归一化。

### 3.4 OAGP（本项目提出的方法）

分别用 64 张干净图和 64 张遮挡图得到 $I^{clean}$、$I^{occ}$，在每个可剪枝层内按均值归一化：
$$\tilde I^{c}_j = \frac{I^{c}_j}{\mathrm{mean}_{k\in l}(I^{c}_k)+\epsilon},\quad c\in\{clean, occ\}$$
然后合并：
$$S_j = (1-\alpha)\,\tilde I^{clean}_j + \alpha\,\tilde I^{occ}_j,\qquad \alpha = 0.5\ \text{（默认）}$$
剪掉每层中 $S_j$ 最小的权重。

- **OAGP-max**：$S_j=\max(\tilde I^{clean}_j, \tilde I^{occ}_j)$，即保留"对任一条件重要"的权重，更直接地对应"不要剪掉遮挡时依赖的权重"这一动机。
- **OAGP 与 Mixed-Taylor 的区别**是我们方法真正的贡献点：分条件计算 + 逐层归一化 + 显式权重 $\alpha$。Mixed-Taylor 用来单独检验这一点。归一化的作用是让两种条件在合并时尺度相当；它的风险是：如果某一条件的分数主要是噪声，归一化会把噪声放大到同等权重（见第 7 节）。

### 3.5 剪枝流程

- **一次性（one-shot）、非结构化、逐层相同稀疏度**。我们比较的是打分准则，不是剪枝调度。
- **可剪枝层**：除第一层 conv 外的全部 19 个 Conv2d（16 个 3×3 + 3 个下采样 1×1），共 11,157,504 个参数，占模型总参数（11,208,318）的 99.55%。不剪 BN、bias 和最后的 fc。
- 步骤：加载 Dense-Aug → 计算分数 → 每层剪掉分数最低的 $p$ 比例 → （可选）微调，微调中每步之后重新施加掩码 → 在固定测试遮挡上评估。
- 每次剪枝后、微调后都检查：各层实际稀疏度 = 目标值，被剪权重恒为 0，排除层未被改动。

## 4. 实验设置

### 4.1 数据

- `sklearn.datasets.fetch_lfw_people(funneled=True, min_faces_per_person=20, color=True)`：**3023 张图，62 个身份**，每人 20–530 张，最大类（George W Bush）占 17.5%。
- 裁剪：funneled 图中以人脸为中心的 **128×128 正方形**区域（y 68–196，x 61–189），以原生分辨率输入网络，不放大到 224。理由：sklearn 默认裁剪只有 125×94，放大到 224 只增加约 3 倍计算、不增加信息，而剪枝实验需要跑很多组；正方形裁剪也避免非等比拉伸。（`configs/default.yaml` 中改 `img_size: 224` 即可切换。）
- **按身份分层划分原图** 70/15/15：train 2121 / val 451 / test 451，每个身份在每个子集中至少 3 张。先划分再遮挡，同一原图不会以任何形式出现在两个子集里。划分索引保存在 `results/splits/`。
- 这是**闭集身份分类**，不是 LFW 官方的人脸验证协议，报告和展示中都要说明。

### 4.2 遮挡

| 用途 | 设置 |
|---|---|
| Dense-Aug 训练 / 增强微调 | 每张图以 0.5 概率遮挡，面积 ~U(10%, 30%)，位置随机 |
| 打分（Occ-Taylor / OAGP） | 从训练集抽样，面积 ~U(10%, 30%)，固定种子 |
| 验证 / 测试 | 0%、10%、30%、50% 四个等级；位置用独立种子**一次生成并保存**（`results/masks/`）；测试每张图每个等级 3 个位置取平均，验证 1 个 |
| 未见过的遮挡（E6） | 眼部横条（墨镜）、下半脸（口罩）、灰色块、噪声块——只用于评估 |

所有方法都在**完全相同的遮挡图**上评估；测试集从不参与模型选择、打分或调参。

### 4.3 模型与训练

- ImageNet 预训练 ResNet-18，fc 换成 62 类；交叉熵损失。
- AdamW：backbone lr 1e-4、head lr 1e-3，weight decay 0.01（BN 与 bias 不加），逐步 cosine 衰减；batch 32；仅水平翻转增强；**25 epochs**（15 epoch 的初步结果显示 Dense-Aug 在 50% 遮挡验证集上仍在上升，见第 7 节）。
- **模型选择**：两个 dense 模型统一选"验证集四个遮挡等级平均准确率最高"的 epoch。
- Dense-Clean 与 Dense-Aug 使用相同的初始权重（含新 fc）、batch 顺序、翻转和训练预算，唯一区别是训练时的遮挡。
- 全流程固定随机种子、cuDNN 确定性模式；同一 seed 重复运行，所有数字逐位一致（已验证）。

### 4.4 公平性控制

| 方法 | 打分样本（干净 / 遮挡） | 反传次数 |
|---|---|---|
| Random | 0 / 0 | 0 |
| Magnitude | 0 / 0 | 0 |
| Clean-Taylor | 128 / 0 | 128 |
| Occ-Taylor | 0 / 128 | 128 |
| Mixed-Taylor | 64 / 64 | 128 |
| OAGP（α=0.5） | 64 / 64 | 128 |
| OAGP-max | 64 / 64 | 128 |

- 所有方法从**同一个 Dense-Aug checkpoint** 出发（每个 seed 一个）；打分样本从训练集用固定种子抽取，各方法共用同一批原图。
- 这是**固定计算量**的比较：OAGP 每种条件只看到 64 个样本，比单条件方法少；如实说明。Magnitude 和 Random 不需要反传，如实报告其更低的成本。
- 任何使用更大打分预算的分析（如 α 消融时预先在更大集合上计算分数）单独报告，不与主实验混在一起。

### 4.5 微调协议

每个"方法 × 稀疏度"都报告：

1. **不微调（one-shot）**：剪枝后直接评估——对打分准则最纯粹的检验，准则之间的差异在这里最明显。
2. **增强微调（主设置）**：与 Dense-Aug 相同的遮挡增强配方，初定 5 epochs、AdamW lr 1e-4、cosine，按验证集选 epoch；掩码在每步后重新施加。
3. **干净微调（可选）**：只用干净图片微调，用来区分"鲁棒性来自打分准则"还是"来自微调时的增强"。

所有方法的微调配方和预算完全相同。

### 4.6 指标

- **分类**：各遮挡等级下的 accuracy 与 balanced accuracy（各类召回率平均）；robustness drop $\Delta A(r)=A_{clean}-A_{occ}(r)$，并同时给出绝对准确率（drop 小不代表模型好）。
- **压缩**：各可剪枝层的实际稀疏度、全模型非零参数数、按非零参数计算的压缩比。说明：非结构化稀疏不会自动减小 dense checkpoint 体积或推理延迟，我们不声称加速。
- **计算**：dense 训练时间、打分时间、剪枝时间、微调时间（GPU 同步计时，注明设备）。

### 4.7 统计

- **至少 3 个 seed**（42、43、44）：每个 seed 重新划分数据、重新训练 dense 模型、重新抽打分样本。报告 mean ± std 和每个 seed 的结果。
- **同一 seed 内的方法比较用配对检验**：对测试原图做配对 bootstrap（先把每张图 3 个遮挡位置的结果取平均），给出 95% 置信区间；必要时补充 McNemar 检验。
- 测试集 451 张图，1 张图 ≈ 0.22 个百分点；差异小于约 1–2 个百分点且置信区间跨 0 时，不下结论。同一图片的 3 个遮挡版本不当作独立样本。

## 6. 预期与可检验的预测

在开始剪枝前把预测写下来，避免事后解释：

1. 在 ≤ 50% 稀疏度下，所有方法（含 Magnitude）与 dense 差别很小；差异只会在拐点附近及以上出现。
2. 不微调时准则之间的差异最大；增强微调后差异明显缩小。
3. **Occ-Taylor 明显优于 Clean-Taylor**（理由见第 7 节诊断）。
4. **OAGP（α=0.5）可能不如 Occ-Taylor**：逐层均值归一化会把干净分数中的噪声放大到与遮挡分数同等的权重。若 E5 中最优 α 接近 1，即支持这一解释。
5. 若 E7 显示干净与遮挡重要性的掩码重叠率很高（如 > 90%），那么任何融合方式都不会带来明显差异——这本身是一个有价值的结论。

**观察与对后续实验的影响**

1. **遮挡增强几乎不损失干净精度**（差异不显著），但大幅提升遮挡鲁棒性。Dense-Aug 足以作为剪枝起点；50% 遮挡下只有 64.5%，剪枝造成的退化有足够空间被测出来。
2. **干净数据上的梯度信号很弱。** 在 Dense-Aug 上：训练集 clean loss 0.0049，occluded loss 0.039；卷积权重的梯度范数 clean 0.42，occluded 8.39（约 20 倍）。clean-Taylor 分数很大程度上是"噪声 × |w|"——这是第 6 节预测 3、4 的依据。可选的补救：在训练集中预留一小块不参与训练的 calibration 子集用于打分，或使用 Fisher 准则（E5）。
3. **balanced accuracy 比 accuracy 低约 5 个百分点**，遮挡下差距更大：少数类更难，必须同时报告。
4. **模型选择准则会影响结果**：Dense-Clean 按"平均遮挡准确率"选中了第 4 个 epoch（它的干净验证准确率在第 14–15 个 epoch 更高，约 92%）。规则对两个模型一致，报告中说明。
5. **Dense-Aug 在第 15 个 epoch 仍在提升**（50% 遮挡验证准确率），因此正式版本改为 25 epochs，重训后冻结 Dense-Aug，再开始所有剪枝实验。
6. **算力充裕**：整个 dense 流程约 1 分钟，多 seed、完整稀疏度扫描和 α 消融都可行。

### 10.3 Q&A 准备（每人都要能回答）

| 可能的问题 | 回答要点 |
|---|---|
| OAGP 和直接在混合数据上算 Taylor 有什么区别？ | 分条件计算 + 逐层归一化 + 显式 α；Mixed-Taylor 基线就是为检验这一点设置的 |
| 为什么用逐样本梯度而不是 batch 梯度？ | batch 梯度先平均再取绝对值，正负抵消，与期望公式不等价；128 个样本的逐样本反传只需几秒 |
| 为什么不报告 40% 稀疏度？ | 低稀疏度下 ResNet-18 几乎无损，比不出差别；E2 先找拐点 |
| 微调会不会抹平差异？ | 会，所以同时报告不微调和微调后的结果 |
| OAGP 是否只是匹配了测试遮挡？ | E6 用训练和打分中都没出现过的遮挡类型检验 |
| 差异显著吗？ | 3 个 seed + 配对 bootstrap；测试集 451 张，小于 1–2 个百分点不下结论 |
| 为什么输入是 128 而不是 224？ | 原图人脸只有约 125 像素，放大只增加计算；配置可切换 |
| 稀疏模型会更快吗？ | 非结构化稀疏不会自动加速，我们只报告非零参数数；结构化剪枝是后续方向 |
| 为什么 clean-Taylor 可能很差？ | 模型在干净训练图上 loss≈0，梯度范数只有遮挡的约 1/20，分数大部分是噪声 |
| 这和课程有什么关系？ | 模型压缩（剪枝）+ 数据选择（用哪些样本估计重要性，E8 / coreset） |
| 这个准确率能和 LFW 论文比较吗？ | 不能：这是 62 类闭集分类，不是官方人脸验证协议 |

## 11. 风险与预案

| 风险 | 预案 |
|---|---|
| 各方法差别很小 | 用不微调结果、E7 重叠率和第 7 节诊断解释原因，作为负面结果如实报告 |
| Dense-Aug 精度不足 | 已排除（干净 93.1%、30% 遮挡 85.5%） |
| 时间不够跑完所有 seed | 摘要和展示先用 seed 42，明确标注单 seed；E4 放在展示之后 |
| 组员环境不一致 | `requirements.txt` 锁定版本；notebook 第一格打印 Python 路径；结果 JSON 记录软硬件版本 |
| LFW 下载失败 | 不换数据集；手动下载 `lfw-funneled.tgz` 放到 `data/sklearn/lfw_home/` |
| 不同机器结果略有差异 | 同一机器逐位可复现；跨机器（不同 GPU / cuDNN）可能有小差异，正式结果统一在一台机器上跑 |
