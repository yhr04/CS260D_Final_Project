# CS 260D Final Project 计划：遮挡感知梯度剪枝（Occlusion-Aware Gradient Pruning, OAGP）

> 更新：2026-11-21 · 维护者：全组 · 代码与结果见 README

**一句话：** 在**相同权重稀疏度、相同梯度打分预算**下，用"干净 + 遮挡"两种输入来估计参数重要性并据此剪枝，能否比只看权重大小或只看干净数据的剪枝更好地保住遮挡人脸的识别性能？

**实验设置：** 在 **CASIA-WebFace**（10,572 个身份、49 万张，112×112 对齐）上训练人脸特征；在 **LFW 人脸验证（6000 对）** 及其遮挡版本上测试，AgeDB-30、CALFW、CPLFW 作为补充。这是遮挡人脸识别文献（PDSN、FROM）的标准做法；一个 dense 模型约 45 分钟，剪枝 + 评估以分钟计，算力足够跑完整的对比和消融。

## 1. 研究问题与动机

**问题。** 部署在边缘设备上的人脸识别模型需要压缩，而真实场景里人脸经常被口罩、墨镜、手、头发等遮挡。剪枝通常根据"参数有多重要"决定删掉哪些权重，但重要性几乎总是在**干净数据**上估计（或者只看权重大小）。

**为什么这是个问题。** 已有研究发现，剪枝对整体准确率影响很小时，对少数、困难或分布外样本的伤害却不成比例（Hooker et al., 2019；Liebenwein et al., 2021）。遮挡人脸正是这类困难输入：模型在遮挡下依赖的可能是另一批权重（利用未遮挡区域的特征、在信息缺失时做补偿的通道）。只用干净数据判断重要性，这些权重可能因为在干净图上"不重要"而被剪掉。

**与近期研究的联系。** 大语言模型的训练后剪枝（SparseGPT、Wanda）同样依赖一小批"校准数据"来估计重要性。近两年的研究发现校准数据的选择会显著影响剪枝效果，尤其在高稀疏度下；而且只看平均指标会掩盖某些能力上的大幅差异（Williams & Aletras, 2024；"Beware of Calibration Data for Pruning LLMs", 2024）。我们研究的是同一个问题在视觉中的版本：**当部署条件（遮挡）与训练条件不同时，应该用什么数据来估计剪枝重要性？**

**想法。** 分别在干净和合成遮挡的输入上计算一阶 Taylor 重要性，逐层归一化后加权合并，再按合并分数剪枝（OAGP）。方法不需要额外优化，只改变**用什么数据估计重要性**。

**假设。** 在相同稀疏度和相同打分预算下，融合干净与遮挡重要性，比只用其中一种或只看权重大小，能在遮挡输入上保留更好的识别性能，同时不明显损害干净输入上的性能。

**我们不预设结论。** 项目的价值在于把"有效 / 无效 / 为什么"讲清楚（见第 6 节的预测与第 8 节的梯度诊断）。

## 3. 方法

### 3.1 问题定义

网络 $f_w$，可剪枝参数集合 $\mathcal{P}$（见 3.5）。对每个可剪枝层 $l$ 和目标稀疏度 $p$，选择二值掩码 $m_l$，满足 $\|m_l\|_0 = \lfloor (1-p)|w_l| \rfloor$；剪枝后模型为 $f_{w\odot m}$。目标：$f_{w\odot m}$ 在干净和遮挡输入上都保持高验证性能。

### 3.2 合成遮挡算子

$x^{occ} = T_M(x)$：在 $[0,1]$ 像素空间、归一化之前，把区域 $M$ 置为黑色（0）。两类遮挡：

- **随机方块**：面积占整张图比例 $r$，边长 $\mathrm{round}(\sqrt{r\,HW})$，位置均匀随机。用于训练增强、打分和"同分布"测试。
- **按人脸区域遮挡**（仅用于测试）：112×112 对齐人脸使用固定的五点模板，眼睛、鼻子、嘴的位置在每张图中基本固定，因此直接按模板坐标遮住双眼（墨镜）、口鼻（口罩）、上半脸、下半脸——参照 FROM 构造遮挡 LFW 的方式。这些类型在训练和打分中从未出现。坐标见 `faceverif.REGION_RECTS`，样例见 `figures/occlusion_conditions.png`。

### 3.3 重要性准则

所有梯度类准则都在**同一个 Dense-Aug checkpoint** 上计算，BN 处于 eval 模式，损失为训练所用的 CosFace 损失。

- **Random**：随机分数（下界）。
- **Magnitude**：$I_j = |w_j|$。
- **一阶 Taylor（逐样本估计）**：
  $$I_j(\mathcal{S}) = \frac{1}{|\mathcal{S}|}\sum_{n\in\mathcal{S}} \left| w_j \,\frac{\partial \ell(x_n, y_n)}{\partial w_j} \right|$$
  每个样本单独反传，精确对应"逐样本绝对贡献的期望"。mini-batch 版本 $|w_j\,\partial L_b/\partial w_j|$ 会在 batch 内正负抵消，与上式不等价，只作为消融。
  - **Clean-Taylor**：$\mathcal{S}$ 全为干净训练图；**Occ-Taylor**：全为遮挡训练图（面积 ~U(10%, 30%)）；**Mixed-Taylor**：一半一半，直接合并计算。

### 3.4 OAGP

分别用一半预算的干净图和遮挡图得到 $I^{clean}$、$I^{occ}$，在每个可剪枝层内按均值归一化：
$$\tilde I^{c}_j = \frac{I^{c}_j}{\mathrm{mean}_{k\in l}(I^{c}_k)+\epsilon},\quad c\in\{clean, occ\}$$
$$S_j = (1-\alpha)\,\tilde I^{clean}_j + \alpha\,\tilde I^{occ}_j,\qquad \alpha = 0.5\ \text{（默认）}$$

- **OAGP-max**：$S_j=\max(\tilde I^{clean}_j, \tilde I^{occ}_j)$，保留"对任一条件重要"的权重。
- **OAGP 与 Mixed-Taylor 的区别**（分条件计算 + 逐层归一化 + 显式 $\alpha$）是方法真正的贡献点，用 Mixed-Taylor 单独检验。
- **风险**：若某一条件的分数主要是噪声，逐层归一化会把噪声放大到与另一条件同等的权重。可选修正：按每层分数的信噪比（跨样本的均值 / 标准差）自适应决定 $\alpha_l$（**OAGP-SNR**，E6）。
- **可选扩展：激活类准则（Wanda 式）**：$I_j = |w_j|\cdot\|X_{in(j)}\|_2$，只需前向传播、不需要标签。用干净 / 遮挡 / 混合的校准数据分别计算，检验"遮挡感知的校准数据"是否对不同类型的准则都有效（E9）。

### 3.5 剪枝流程

- **一次性（one-shot）、非结构化、逐层相同稀疏度**；比较的是打分准则，不是剪枝调度。
- **可剪枝层**：ResNet-18 除第一层 conv 外的全部 19 个 Conv2d（16 个 3×3 + 3 个下采样 1×1），共 11,157,504 个参数。不剪 BN、bias、第一层 conv、512 维嵌入层（`model.fc`）和 CosFace 分类头。
- 步骤：加载 Dense-Aug → 计算分数 → 每层剪掉分数最低的 $p$ 比例 → （可选）微调，每步后重新施加掩码 → 在固定遮挡测试对上评估。
- 每次都检查：各层实际稀疏度等于目标、被剪权重恒为 0、排除层未被改动。

## 4. 实验设置

### 4.1 数据

| 项目 | 设置 |
|---|---|
| 训练集 | CASIA-WebFace 112×112 对齐版（Kaggle：`yakhyokhuja/webface-112x112`）：490,623 张、10,572 个身份（每人 2–802 张，中位数 27）；留出后训练 481,210 张、10,361 个身份 |
| 测试集 | LFW 112×112 对齐版，标准 6000 对、10 折（每折 300 正 + 300 负）验证协议（Kaggle：`yakhyokhuja/agedb-30-calfw-cplfw-lfw-aligned-112x112`，同包内 AgeDB-30、CALFW、CPLFW 格式相同，作为补充测试） |
| 验证集（模型选择、α 选择） | 从 ≥5 张图的身份中**留出 2%**（211 个身份、9,413 张，不参与训练），构造 3000 正对 + 3000 负对，按 10 折排列。LFW 只做最终测试，**从不用于选模型或调参** |
| 遮挡测试 | 每对中的**第二张图**加遮挡（模拟"遮挡的查询图 vs 干净的底库图"）；随机方块位置用固定种子生成并保存（`results/masks/`），所有方法共用 |
| 遮挡类型 | 随机方块 10% / 30% / 50%（与训练同分布）；按区域遮挡：双眼、口鼻、上半脸、下半脸（训练与打分中从未出现） |
| 真实遮挡（可选） | ROF（MIT 许可，真实墨镜 / 口罩），需按同一模板对齐后使用 |
| 存储 | zip 不解压，直接解码成 `data/cache/casia_112.npy`（uint8 memmap，18.5 GB，约 1.5 分钟），DataLoader worker 按批读取 |

数据格式：`webface_112x112/id_<k>/<k>_<j>.jpg`；验证包为每个数据集 12000 张 bmp + `<name>_ann.txt`，第 t 对 = 图 2t 与 2t+1。均为 RGB、已对齐（已用肤色通道统计确认不是 BGR）。

### 4.2 模型与训练

| 项目 | 设置 |
|---|---|
| 网络 | ImageNet 预训练 ResNet-18 主干，全局池化后接 512 维嵌入层（FC 无 bias + BN1d），112×112 原生分辨率输入 |
| 损失 | CosFace（$s=64,\ m=0.35$），分类头在 fp32 计算 |
| 优化 | SGD momentum 0.9，lr 0.1，wd 5e-4（BN 与 bias 不加），batch 256，1 epoch 线性 warm-up + 逐步 cosine，20 epochs，bf16 autocast |
| 增强 | 水平翻转；Dense-Aug 额外以 0.5 概率加随机方块遮挡（面积 ~U(10%, 30%)） |
| 模型选择 | 留出身份验证对上"干净 + 方块 10/30/50%"四种条件平均验证准确率最高的 epoch |
| 评估 | 嵌入 = normalize(f(x) + f(flip(x)))，余弦相似度 |

- Dense-Clean 与 Dense-Aug 使用相同的初始权重（含 CosFace 头）、数据顺序、翻转和训练预算，唯一区别是训练时的遮挡。
- 全流程固定随机种子、cuDNN 确定性模式；每个 epoch 保存完整状态，可断点续训。
- **实测算力**（RTX 3070 Ti Laptop）：训练约 5,000 张/秒，loader 不是瓶颈（Windows 上每个 epoch 启动 worker 约 20 秒）；一个 epoch 约 2 分钟，一个 dense 模型约 45 分钟；一次完整测试评估（4 个数据集 × 8 种条件）约 30 秒。

### 4.3 公平性控制

| 方法 | 打分样本（干净 / 遮挡） | 反传次数 |
|---|---|---|
| Random、Magnitude | 0 / 0 | 0 |
| Clean-Taylor | B / 0 | B |
| Occ-Taylor | 0 / B | B |
| Mixed-Taylor、OAGP、OAGP-max | B/2 / B/2 | B |

- 预算 B 默认 1024（1 万个类别下 128 个样本覆盖太少），并做 128 / 1024 / 4096 的预算消融（E8）。
- 所有方法从**同一个 Dense-Aug checkpoint** 出发；打分样本用固定种子从训练集抽取，各方法共用同一批原图。
- 这是**固定计算量**比较：OAGP 每种条件只看到一半样本，如实说明。Magnitude 和 Random 不需要反传，如实报告其更低成本。
- 用更大预算做的分析（如 α 消融时预先算好大样本分数再复用）单独报告。

### 4.4 微调协议

每个"方法 × 稀疏度"都报告：

1. **不微调（one-shot）**：对打分准则最纯粹的检验。
2. **增强微调（主设置）**：与 Dense-Aug 相同的配方，1–2 epochs（每 epoch 约 2 分钟）；掩码每步后重新施加。
3. **干净微调（可选）**：区分"鲁棒性来自打分准则"还是"来自微调时的增强"。

### 4.5 指标

- LFW 验证准确率（标准 10 折交叉验证选阈值），分别在干净对、各类遮挡对上报告；同时报告 TAR@FAR=1e-3（3000 个负对，只有 3 次误识，噪声较大，仅作参考）和 AUC。补充：AgeDB-30、CALFW、CPLFW。
- **压缩**：各层实际稀疏度、全模型非零参数数、压缩比。非结构化稀疏不会自动减小 dense checkpoint 体积或推理延迟，不声称加速。
- **计算**：训练、打分、剪枝、微调时间（GPU 同步计时，注明设备）。

### 4.6 统计

- 训练 1 个 seed（42）的 dense 模型；剪枝比较的随机性主要来自打分样本，关键对比用 **3 个打分种子**（不同的打分样本）报告 mean ± std。时间允许再加 1 个训练 seed。
- **配对检验**：所有方法在同一批 6000 对上评估，保存每对的相似度；对**对**做配对 bootstrap，给出 95% 置信区间；固定阈值下可用 McNemar 检验。LFW 10 折的标准差也一并报告。
- 差异的置信区间跨 0 时不下结论。

## 6. 预期与可检验的预测

剪枝前先写下预测，避免事后解释：

1. 在 ≤50% 稀疏度下各方法（含 Magnitude）差别很小，差异只在拐点附近及以上出现。
2. 不微调时准则之间的差异最大，增强微调后明显缩小。
3. **Occ-Taylor 优于 Clean-Taylor 的幅度可能不大**：Dense-Aug 上遮挡梯度范数只有干净梯度的约 1.6 倍（第 8 节），干净梯度并不是噪声，两种分数可能高度相关。
4. **OAGP（α=0.5）是否优于单一条件取决于两种分数的差异**：若两者的掩码重叠率高，融合几乎无影响；若最优 α 接近 1、OAGP-SNR 优于 OAGP，则说明干净分数信息量较低。
5. 在按区域遮挡这类未见过的遮挡上，遮挡感知准则的优势会缩小但不消失。
6. 若干净与遮挡重要性的掩码重叠率很高（> 90%），任何融合方式都不会带来明显差异——本身就是有价值的结论。

## 7. 代码与工作约定

- **入口是 notebook**（`notebooks/`，中文说明，图表英文）；所有逻辑在 `src/occprune/`，notebook 只调用函数。
  - `01_data`：数据下载说明、缓存、留出划分、固定遮挡、吞吐测试（E0）
  - `02_dense_baselines`：Dense-Clean / Dense-Aug 训练与验证（E1）

  - `04_calibration_selection`：打分样本选择（coreset 类选择器 × 预算，E8 / E10）
  - 之后的消融（α、打分种子等，E6、E7）沿用 `prune_run` 与 `prune_report`，新 notebook 依次编号

- `results/`、`figures/` 进 git；`data/`、`checkpoints/` 不进 git。
- 环境：`requirements.txt`（pip / conda）或 `pyproject.toml` + `uv.lock`（uv）。
- 新功能配单元测试：打分形状与权重一致、掩码在微调中保持、稀疏度达标、排除层不变、验证对的划分与阈值选择正确。

## 8. 当前结果：Dense 基线（E1，seed 42，20 epochs）

**环境：** Windows 11，RTX 3070 Ti Laptop GPU（8 GB），PyTorch 2.9.1 + CUDA 12.8，Python 3.12。纯训练时间 Dense-Clean 41 分钟、Dense-Aug 54 分钟。

LFW 验证准确率（%，10 折 mean ± std；每对第二张图遮挡）：

| 模型 | 选中 epoch | Clean | 方块 10% | 方块 30% | 方块 50% | 双眼 | 口鼻 | 上半脸 | 下半脸 |
|---|---|---|---|---|---|---|---|---|---|
| Dense-Clean | 18 | 98.88 ± 0.41 | 97.08 ± 0.56 | 83.73 ± 1.04 | 65.62 ± 1.61 | 92.77 ± 1.41 | 90.10 ± 1.84 | 92.00 ± 1.42 | 86.30 ± 2.80 |
| Dense-Aug | 20 | 98.72 ± 0.44 | 98.77 ± 0.46 | 96.52 ± 0.54 | 90.65 ± 1.03 | 96.93 ± 0.41 | 96.02 ± 1.21 | 94.87 ± 0.89 | 94.83 ± 0.95 |

**Dense-Aug − Dense-Clean**（6000 对配对 bootstrap 95% CI）：clean −0.17 [−0.43, +0.10]；方块 10% +1.68 [+1.28, +2.10]；30% +12.78 [+11.92, +13.73]；50% +25.03 [+23.68, +26.33]；双眼 +4.17；口鼻 +5.92；上半脸 +2.87；下半脸 +8.53（区域遮挡的 CI 均不跨 0，见 `results/dense/bootstrap_lfw_seed42.json`）。补充干净准确率（Clean / Aug）：AgeDB-30 89.20 / 88.27，CALFW 90.92 / 90.78，CPLFW 84.42 / 83.72。

**观察**

1. 遮挡增强不损失干净精度（差异不显著），大幅提升方块遮挡鲁棒性；在**训练中从未见过的区域遮挡**上也一致提升（+2.9 到 +8.5 个百分点），说明不只是匹配了训练遮挡分布。
2. **梯度诊断**：Dense-Aug 在训练图上 clean loss 4.79、occluded loss 9.34；卷积权重梯度范数 clean 30.5、occluded 49.2，比值约 **1.6 倍**（Dense-Clean 上为 2.2 倍）。CASIA 训练远未拟合，干净梯度不是噪声——这是第 6 节预测 3、4 的依据。
3. Dense-Aug 在第 20 个 epoch 仍在提升（选中最后一个 epoch），若时间允许可加长训练；但剪枝比较只需要一个固定起点，暂不重训。
4. LFW 干净准确率 98.9% 接近饱和；方块 30/50% 和区域遮挡上的区分度足够用于剪枝对比。

### 10.3 Q&A 准备（每人都要能回答）

| 可能的问题 | 回答要点 |
|---|---|
| 为什么用 CASIA-WebFace + LFW？ | 遮挡人脸识别文献（PDSN、FROM）的标准协议；开放集验证才是真实人脸识别任务；规模足够让剪枝效应显现，同时一块笔记本 GPU 45 分钟就能训练一个模型 |
| 为什么只遮挡第二张图？ | 模拟真实场景：底库是干净证件照，查询图被遮挡；与 FROM 等工作的遮挡 LFW 构造一致 |
| OAGP 和直接在混合数据上算 Taylor 有什么区别？ | 分条件计算 + 逐层归一化 + 显式 α；Mixed-Taylor 基线专门检验这一点 |
| 为什么用逐样本梯度？ | batch 梯度先平均再取绝对值会正负抵消，与期望公式不等价；逐样本反传的代价完全可以接受 |
| 为什么不报告低稀疏度？ | 低稀疏度下几乎无损，比不出差别；先扫描找拐点 |
| 微调会不会抹平差异？ | 会，所以同时报告不微调和微调后的结果 |
| OAGP 是否只是匹配了测试遮挡？ | 按区域遮挡（墨镜、口罩等）在训练和打分中从未出现，专门检验这一点；可选 ROF 真实遮挡 |
| 差异显著吗？ | 6000 对上的配对 bootstrap、3 个打分种子、LFW 10 折标准差；置信区间跨 0 不下结论 |
| LFW 有没有被用来调参？ | 没有；模型选择和 α 选择都用 CASIA 留出身份构造的验证对 |
| 稀疏模型会更快吗？ | 非结构化稀疏不会自动加速，只报告非零参数数；结构化剪枝是后续方向 |
| 干净梯度和遮挡梯度差多少？ | Dense-Aug 上遮挡梯度范数约为干净的 1.6 倍；CASIA 训练远未拟合，两种分数都有信息量，差异主要看掩码重叠率 |
| 和课程的关系？ | 模型压缩（剪枝）+ 数据选择（用哪些样本估计重要性；与 LLM 校准数据、coreset 相关） |
