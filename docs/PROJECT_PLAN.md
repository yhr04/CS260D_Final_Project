## 1. 研究问题与动机

**问题。** 部署在边缘设备上的人脸识别模型需要压缩，而真实场景里人脸经常被口罩、墨镜、手、头发等遮挡。剪枝通常根据"参数有多重要"决定删掉哪些权重，但重要性几乎总是在**干净数据**上估计（或者只看权重大小）。

**为什么这是个问题。** 已有研究发现，剪枝对整体准确率影响很小时，对少数、困难或分布外样本的伤害却不成比例（Hooker et al., 2019；Liebenwein et al., 2021）。遮挡人脸正是这类困难输入：模型在遮挡下依赖的可能是另一批权重（利用未遮挡区域的特征、在信息缺失时做补偿的通道）。只用干净数据判断重要性，这些权重可能因为在干净图上"不重要"而被剪掉。

**与近期研究的联系。** 大语言模型的训练后剪枝（SparseGPT、Wanda）同样依赖一小批"校准数据"来估计重要性。近两年的研究发现校准数据的选择会显著影响剪枝效果，尤其在高稀疏度下；而且只看平均指标会掩盖某些能力上的大幅差异（Williams & Aletras, 2024；"Beware of Calibration Data for Pruning LLMs", 2024）。我们研究的是同一个问题在视觉中的版本：**当部署条件（遮挡）与训练条件不同时，应该用什么数据来估计剪枝重要性？**

**想法。** 分别在干净和合成遮挡的输入上计算一阶 Taylor 重要性，逐层归一化后加权合并，再按合并分数剪枝（OAGP）。方法不需要额外优化，只改变**用什么数据估计重要性**。

**假设。** 在相同稀疏度和相同打分预算下，融合干净与遮挡重要性，比只用其中一种或只看权重大小，能在遮挡输入上保留更好的识别性能，同时不明显损害干净输入上的性能。

**我们不预设结论。** 开发集上的诊断（第 8 节）已经给出一个可能对 OAGP 不利的现象：收敛模型在干净训练数据上的梯度信号很弱。项目的价值在于把"有效 / 无效 / 为什么"讲清楚。

## 3. 方法

### 3.1 问题定义

网络 $f_w$，可剪枝参数集合 $\mathcal{P}$（见 3.5）。对每个可剪枝层 $l$ 和目标稀疏度 $p$，选择二值掩码 $m_l$，满足 $\|m_l\|_0 = \lfloor (1-p)|w_l| \rfloor$；剪枝后模型为 $f_{w\odot m}$。目标：$f_{w\odot m}$ 在干净和遮挡输入上都保持高识别性能。

### 3.2 合成遮挡算子

$x^{occ} = T_M(x)$：在 $[0,1]$ 像素空间、归一化之前，把区域 $M$ 置为黑色（0）。两类遮挡：

- **随机方块**：面积占整张图比例 $r$，边长 $\mathrm{round}(\sqrt{r\,HW})$，位置均匀随机。用于训练增强、打分和"同分布"测试。
- **按人脸区域遮挡**（仅用于测试）：112×112 对齐人脸使用固定的五点模板，眼睛、鼻子、嘴的位置在每张图中基本固定，因此可以直接按模板坐标遮住双眼（墨镜）、口鼻（口罩）、上半脸、下半脸、左半脸、右半脸——参照 FROM 构造遮挡 LFW 的方式。这些类型在训练和打分中从未出现。

### 3.3 重要性准则

所有梯度类准则都在**同一个 Dense-Aug checkpoint** 上计算，BN 处于 eval 模式。主实验的损失是训练所用的 CosFace 损失（开发集是交叉熵）。

- **Random**：随机分数（下界）。
- **Magnitude**：$I_j = |w_j|$。
- **一阶 Taylor（逐样本估计）**：
  $$I_j(\mathcal{S}) = \frac{1}{|\mathcal{S}|}\sum_{n\in\mathcal{S}} \left| w_j \,\frac{\partial \ell(x_n, y_n)}{\partial w_j} \right|$$
  每个样本单独反传，精确对应"逐样本绝对贡献的期望"。mini-batch 版本 $|w_j\,\partial L_b/\partial w_j|$ 会在 batch 内正负抵消，与上式不等价，只作为消融。
  - **Clean-Taylor**：$\mathcal{S}$ 全为干净训练图；**Occ-Taylor**：全为遮挡训练图（面积 ~U(10%, 30%)）；**Mixed-Taylor**：一半一半，直接合并计算。

### 3.4 OAGP

分别用一半预算的干净图和遮挡图得到 $I^{clean}$、$I^{occ}$，在每个可剪枝层内按均值归一化：
$$\tilde I^{c}_j = \frac{I^{c}_j}{\mathrm{mean}_{k\in l}(I^{c}_k)+\epsilon},\quad c\in\{clean, occ\}$$
$$S_j = (1-\alpha)\,\tilde I^{clean}_j + \alpha\,\tilde I^{occ}_j,\qquad \alpha = 0.5\ \text{（默认）}$$

- **OAGP-max**：$S_j=\max(\tilde I^{clean}_j, \tilde I^{occ}_j)$，保留"对任一条件重要"的权重。
- **OAGP 与 Mixed-Taylor 的区别**（分条件计算 + 逐层归一化 + 显式 $\alpha$）是方法真正的贡献点，用 Mixed-Taylor 单独检验。
- **风险**：若某一条件的分数主要是噪声，逐层归一化会把噪声放大到与另一条件同等的权重（见第 8 节）。可选修正：按每层分数的信噪比（跨样本的均值 / 标准差）自适应决定 $\alpha_l$（**OAGP-SNR**，E5）。
- **可选扩展：激活类准则（Wanda 式）**：$I_j = |w_j|\cdot\|X_{in(j)}\|_2$，只需前向传播、不需要标签。用干净 / 遮挡 / 混合的校准数据分别计算，检验"遮挡感知的校准数据"是否对不同类型的准则都有效（E8）。

### 3.5 剪枝流程

- **一次性（one-shot）、非结构化、逐层相同稀疏度**；比较的是打分准则，不是剪枝调度。
- **可剪枝层**：ResNet-18 除第一层 conv 外的全部 19 个 Conv2d（16 个 3×3 + 3 个下采样 1×1），共 11,157,504 个参数。不剪 BN、bias、第一层 conv，以及输出层（开发集的分类 fc；主实验的 512 维嵌入层和 CosFace 分类头）。
- 步骤：加载 Dense-Aug → 计算分数 → 每层剪掉分数最低的 $p$ 比例 → （可选）微调，每步后重新施加掩码 → 在固定遮挡测试集上评估。
- 每次都检查：各层实际稀疏度等于目标、被剪权重恒为 0、排除层未被改动。

## 4. 实验设置

### 4.1 主实验数据：CASIA-WebFace → LFW 验证

| 项目 | 设置 |
|---|---|
| 训练集 | CASIA-WebFace 112×112 对齐版（Kaggle：`yakhyokhuja/webface-112x112`，约 10.6K 身份、49.1 万张） |
| 测试集 | LFW 112×112 对齐版，标准 6000 对验证协议（Kaggle：`yakhyokhuja/agedb-30-calfw-cplfw-lfw-aligned-112x112`，同包内还有 AgeDB-30、CALFW、CPLFW 作为补充测试） |
| 验证集（模型选择、α 选择） | 从 CASIA-WebFace 中**留出约 2% 的身份**（不参与训练），在这些身份上构造 3000 正对 + 3000 负对的验证对。LFW 只做最终测试，**从不用于选模型或调参** |
| 遮挡测试 | 每对中的**第二张图**加遮挡（模拟"遮挡的查询图 vs 干净的底库图"）；遮挡位置用固定种子一次生成并保存，所有方法共用 |
| 遮挡类型 | 随机方块 10% / 30% / 50%（与训练同分布）；按区域遮挡：双眼、口鼻、上半脸、下半脸（训练与打分中从未出现） |
| 真实遮挡（可选） | ROF（MIT 许可，真实墨镜 / 口罩），需按同一模板对齐后使用 |
| 存储 | 49 万张 × 112×112×3 ≈ 18.5 GB uint8，转成硬盘上的 memmap 文件按批读取（放不进显存） |

**数据获取（M0，已完成，见 notebook 04）：**
1. 两个 Kaggle 数据集可匿名下载（无需账号），zip 放在 `data/_downloads/`（webface.zip 2.7 GB、val.zip 1.4 GB），不需要解压。
2. 实际格式：`webface_112x112/id_<k>/<k>_<j>.jpg`，490,623 张、10,572 个身份（每人 2–802 张，中位数 27）；验证包为 LFW / AgeDB-30 / CALFW / CPLFW 各 12000 张 bmp + `<name>_ann.txt`，第 t 对 = 图 2t 与 2t+1，按标准 10 折 × 600 对（每折 300 正 + 300 负）排列。均为 RGB、已对齐。
3. `prepare_casia` 直接从 zip 解码成 `data/cache/casia_112.npy`（uint8 memmap，18.5 GB，约 1.5 分钟）。留出 211 个身份（9,413 张）构造验证对；训练集 481,210 张、10,361 个身份。
4. 吞吐（RTX 3070 Ti Laptop，bf16）：训练约 5,000 张/秒，loader 不是瓶颈（Windows 上每个 epoch 启动 worker 约 20 秒）；一个 epoch 约 2 分钟，一个 dense 模型 20 epochs 约 45 分钟。

### 4.2 开发集数据：LFW-62 闭集分类

- `fetch_lfw_people(funneled=True, min_faces_per_person=20, color=True)`：3023 张图、62 个身份；128×128 正方形裁剪、原生分辨率输入。
- 按身份 70/15/15 划分原图（train 2121 / val 451 / test 451），先划分再遮挡。
- 测试遮挡：0% / 10% / 30% / 50% 随机方块，每张图每个等级 3 个固定位置取平均。
- 注意：这是闭集分类，**不是** LFW 官方验证协议；它与主实验中的 LFW 验证是两件事，报告中分开表述。

### 4.3 模型与训练

| | 主实验 | 开发集 |
|---|---|---|
| 网络 | ImageNet 预训练 ResNet-18 主干，全局池化后接 512 维嵌入层（FC + BN） | ImageNet 预训练 ResNet-18，fc 换成 62 类 |
| 损失 | CosFace（$s=64,\ m=0.35$，初定） | 交叉熵 |
| 优化（初定） | SGD momentum 0.9，lr 0.1，wd 5e-4，batch 256，cosine，约 20 epochs；先测吞吐和验证集曲线再定 | AdamW（backbone 1e-4 / head 1e-3，wd 0.01），batch 32，cosine，**25 epochs** |
| 增强 | 水平翻转；Dense-Aug 额外以 0.5 概率加随机方块遮挡（面积 ~U(10%, 30%)） | 同左 |
| 模型选择 | 留出身份验证对上"干净 + 遮挡"平均验证准确率最高的 epoch | 验证集上四个遮挡等级平均准确率最高的 epoch |

- Dense-Clean 与 Dense-Aug 使用相同的初始权重、数据顺序、翻转和训练预算，唯一区别是训练时的遮挡。
- 全流程固定随机种子、cuDNN 确定性模式；开发集上已验证同一 seed 重复运行所有数字逐位一致。
- **算力估计（待实测）：** 开发集在 RTX 3070 Ti 上实测约 1,500 张/秒（128px），112px 应更快。据此估计主实验每个 epoch 约 4–6 分钟，一个 dense 模型约 1.5–2 小时，剪枝后微调每组约 10 分钟。实际速度取决于硬盘读取能否跟上，**第一步先测吞吐**；若太慢，先只用一半身份。

### 4.4 公平性控制

| 方法 | 打分样本（干净 / 遮挡） | 反传次数 |
|---|---|---|
| Random、Magnitude | 0 / 0 | 0 |
| Clean-Taylor | B / 0 | B |
| Occ-Taylor | 0 / B | B |
| Mixed-Taylor、OAGP、OAGP-max | B/2 / B/2 | B |

- 预算 B：开发集 128；主实验默认 1024（1 万个类别下 128 个样本覆盖太少），并做 128 / 1024 / 4096 的预算消融。
- 所有方法从**同一个 Dense-Aug checkpoint** 出发；打分样本用固定种子从训练集抽取，各方法共用同一批原图。
- 这是**固定计算量**比较：OAGP 每种条件只看到一半样本，如实说明。Magnitude 和 Random 不需要反传，如实报告其更低成本。
- 用更大预算做的分析（如 α 消融时预先算好大样本分数再复用）单独报告。

### 4.5 微调协议

每个"方法 × 稀疏度"都报告：

1. **不微调（one-shot）**：对打分准则最纯粹的检验。
2. **增强微调（主设置）**：与 Dense-Aug 相同的配方；主实验约 1–2 epochs，开发集 5 epochs；掩码每步后重新施加。
3. **干净微调（可选）**：区分"鲁棒性来自打分准则"还是"来自微调时的增强"。

### 4.6 指标

- **主实验**：LFW 验证准确率（标准 10 折交叉验证选阈值），分别在干净对、各类遮挡对上报告；可加 TAR@FAR=1e-3。补充：AgeDB-30、CALFW、CPLFW 干净准确率。
- **开发集**：各遮挡等级 accuracy 与 balanced accuracy、robustness drop（同时给绝对值）。
- **压缩**：各层实际稀疏度、全模型非零参数数、压缩比。非结构化稀疏不会自动减小 dense checkpoint 体积或推理延迟，不声称加速。
- **计算**：训练、打分、剪枝、微调时间（GPU 同步计时，注明设备）。

### 4.7 统计

- **开发集**：3 个 seed（42、43、44），每个 seed 重新划分、重新训练；报告 mean ± std 和每个 seed 的结果。
- **主实验**：算力只够 1 个完整 seed；关键对比（如 Occ-Taylor vs OAGP）若时间允许再加 1 个打分种子 / 训练种子。
- **配对检验**：同一评估集上对样本（开发集为测试原图，主实验为验证对）做配对 bootstrap，给出 95% 置信区间；固定阈值下可用 McNemar 检验。LFW 10 折的标准差也一并报告。
- 差异的置信区间跨 0 时不下结论；同一图片的多个遮挡版本不当作独立样本。

## 6. 预期与可检验的预测

剪枝前先写下预测，避免事后解释：

1. 在 ≤50% 稀疏度下各方法（含 Magnitude）差别很小，差异只在拐点附近及以上出现；主实验的拐点会比开发集更低（任务更难，冗余更少）。
2. 不微调时准则之间的差异最大，增强微调后明显缩小。
3. **Occ-Taylor 明显优于 Clean-Taylor**（开发集诊断：干净梯度约为遮挡梯度的 1/20）。
4. **OAGP（α=0.5）可能不如 Occ-Taylor**：逐层归一化放大干净分数中的噪声。若最优 α 接近 1、OAGP-SNR 优于 OAGP，即支持这一解释。
5. 在按区域遮挡这类未见过的遮挡上，遮挡感知准则的优势会缩小但不消失。
6. 若干净与遮挡重要性的掩码重叠率很高（> 90%），任何融合方式都不会带来明显差异——本身就是有价值的结论。

## 8. 当前结果：开发集 Dense 基线（D1 初步，15 epochs，seed 42）

**环境：** Windows 11，RTX 3070 Ti Laptop GPU（8 GB），PyTorch 2.9.1 + CUDA 12.8，Python 3.12。每个模型纯训练时间约 21 秒。

| 模型 | 选中 epoch | Clean | Occ 10% | Occ 30% | Occ 50% | Clean BalAcc | Occ 30% BalAcc | Occ 50% BalAcc |
|---|---|---|---|---|---|---|---|---|
| Dense-Clean | 4 | 92.68 | 62.60 | 24.61 | 18.11 | 88.00 | 9.81 | 4.72 |
| Dense-Aug | 14 | 93.13 | 92.68 | 85.51 | 64.52 | 87.41 | 77.75 | 52.66 |

（测试集准确率，%；遮挡等级为 3 个固定位置的平均。）**Dense-Aug − Dense-Clean**（配对 bootstrap 95% CI，451 张测试原图）：clean +0.44 [−2.22, +3.10]；10% +30.08 [+26.68, +33.48]；30% +60.90 [+57.06, +64.82]；50% +46.42 [+42.65, +50.18]。

**观察**

1. 遮挡增强几乎不损失干净精度（差异不显著），但大幅提升遮挡鲁棒性。
2. **干净数据上的梯度信号很弱**：Dense-Aug 在训练集上 clean loss 0.0049、occluded loss 0.039；卷积权重梯度范数 clean 0.42、occluded 8.39（约 20 倍）。这是第 6 节预测 3、4 的依据；主实验中 CASIA 训练不会完全拟合，需要重新测量这一比值。
3. balanced accuracy 比 accuracy 低约 5 个百分点（少数类更难）。
4. Dense-Clean 按"平均遮挡准确率"选中第 4 个 epoch（干净准确率在后期更高），规则对两个模型一致，报告中说明。
5. Dense-Aug 在第 15 个 epoch 仍在提升，正式版改为 25 epochs，重训后冻结。
6. 开发集规模小（测试 451 张，95% 置信区间约 ±2.8 个百分点；62 类对 ResNet-18 过于容易），这正是主实验改用 CASIA-WebFace + LFW 验证的原因。

### 8.2 主实验 Dense 基线（M1，seed 42，20 epochs）

ResNet-18（ImageNet 预训练）+ 512 维嵌入 + CosFace（s=64，m=0.35），SGD lr 0.1，batch 256，bf16；RTX 3070 Ti Laptop 上纯训练 Dense-Clean 41 分钟、Dense-Aug 54 分钟。模型按留出 CASIA 身份验证对（干净 + 方块 10/30/50% 平均）选择。

LFW 验证准确率（%，10 折 mean ± std；每对第二张图遮挡）：

| 模型 | 选中 epoch | Clean | 方块 10% | 方块 30% | 方块 50% | 双眼 | 口鼻 | 上半脸 | 下半脸 |
|---|---|---|---|---|---|---|---|---|---|
| Dense-Clean | 18 | 98.88 ± 0.41 | 97.08 ± 0.56 | 83.73 ± 1.04 | 65.62 ± 1.61 | 92.77 ± 1.41 | 90.10 ± 1.84 | 92.00 ± 1.42 | 86.30 ± 2.80 |
| Dense-Aug | 20 | 98.72 ± 0.44 | 98.77 ± 0.46 | 96.52 ± 0.54 | 90.65 ± 1.03 | 96.93 ± 0.41 | 96.02 ± 1.21 | 94.87 ± 0.89 | 94.83 ± 0.95 |

**Dense-Aug − Dense-Clean**（6000 对配对 bootstrap 95% CI）：clean −0.17 [−0.43, +0.10]；方块 10% +1.68 [+1.28, +2.10]；30% +12.78 [+11.92, +13.73]；50% +25.03 [+23.68, +26.33]；双眼 +4.17；口鼻 +5.92；上半脸 +2.87；下半脸 +8.53（区域遮挡的 CI 均不跨 0，见 `results/casia/casia_dense_bootstrap_lfw_seed42.json`）。补充干净准确率（Clean / Aug）：AgeDB-30 89.20 / 88.27，CALFW 90.92 / 90.78，CPLFW 84.42 / 83.72。

**观察**
1. 与开发集一致：遮挡增强不损失干净精度（差异不显著），大幅提升方块遮挡鲁棒性；在**训练中从未见过的区域遮挡**上也一致提升（+2.9 到 +8.5 个百分点），说明不只是匹配了训练遮挡分布。
2. **梯度比远小于开发集**：Dense-Aug 在训练图上 clean loss 4.79、occluded loss 9.34；卷积权重梯度范数 clean 30.5、occluded 49.2，比值约 **1.6 倍**（开发集约 20 倍；Dense-Clean 上为 2.2 倍）。CASIA 训练远未拟合，干净梯度不是噪声。第 6 节预测 3、4（Clean-Taylor 明显差、OAGP 被噪声拖累）的依据在主实验中弱很多，需要以 M3 的实际结果为准。
3. Dense-Aug 在第 20 个 epoch 仍在提升（选中最后一个 epoch），若时间允许可加长训练；但剪枝比较只需要一个固定起点，暂不重训。
4. LFW 干净准确率 98.9% 接近饱和；方块 30/50% 和区域遮挡上的区分度足够用于剪枝对比。

### 10.3 Q&A 准备（每人都要能回答）

| 可能的问题 | 回答要点 |
|---|---|
| 为什么用 CASIA-WebFace + LFW？ | 遮挡人脸识别文献（PDSN、FROM）的标准协议；开放集验证才是真实人脸识别任务；规模足够让剪枝效应显现 |
| 开发集和主实验的关系？ | 开发集用于快速开发、多 seed 和初步结果；主实验是最终结论；两者结论一致时可信度更高 |
| OAGP 和直接在混合数据上算 Taylor 有什么区别？ | 分条件计算 + 逐层归一化 + 显式 α；Mixed-Taylor 基线专门检验这一点 |
| 为什么用逐样本梯度？ | batch 梯度先平均再取绝对值会正负抵消，与期望公式不等价；逐样本反传的代价完全可以接受 |
| 为什么不报告低稀疏度？ | 低稀疏度下几乎无损，比不出差别；先扫描找拐点 |
| 微调会不会抹平差异？ | 会，所以同时报告不微调和微调后的结果 |
| OAGP 是否只是匹配了测试遮挡？ | 按区域遮挡（墨镜、口罩等）在训练和打分中从未出现，专门检验这一点；可选 ROF 真实遮挡 |
| 差异显著吗？ | 开发集 3 个 seed，主实验配对 bootstrap 与 10 折标准差；置信区间跨 0 不下结论 |
| LFW 有没有被用来调参？ | 没有；模型选择和 α 选择都用 CASIA 留出身份构造的验证对 |
| 稀疏模型会更快吗？ | 非结构化稀疏不会自动加速，只报告非零参数数；结构化剪枝是后续方向 |
| 为什么 clean-Taylor 可能很差？ | 收敛模型在干净训练图上 loss≈0，梯度只有遮挡的约 1/20，分数大部分是噪声 |
| 和课程的关系？ | 模型压缩（剪枝）+ 数据选择（用哪些样本估计重要性；与 LLM 校准数据、coreset 相关） |

## 11. 风险与预案

| 风险 | 预案 |
|---|---|
| CASIA / 验证集下载失败或格式难处理 | 尝试 InsightFace 提供的同类打包数据；仍不行则主实验退回 CelebA 闭集分类（身份标签可从 Hugging Face 镜像获取） |
| 主实验训练太慢（硬盘读取瓶颈） | 先用一半身份；减少 epoch；微调只做 1 epoch |
| 主实验来不及跑完 M3 | 摘要和展示以开发集结果为主、M1 为辅；报告中如实写明主实验完成的部分 |
| 各方法差别很小 | 用不微调结果、重要性重叠率和梯度诊断解释，作为负面结果如实报告 |
| 组员环境不一致 | `requirements.txt` 锁定版本；结果 JSON 记录软硬件；正式结果统一在一台机器上跑 |
| 跨机器结果略有差异 | 同一机器逐位可复现；不同 GPU / cuDNN 可能有小差异，正式结果统一在一台机器上跑 |
